# PR #5 Review-Evidence Protocol

## Purpose

This protocol operationalizes the architectural review on PR #5 without relabeling the current result as an ARC1, ARC2, or ARC3 solver. It asks whether the persistent `PartialTheory` path—not a task dispatch table or a newly added whole-task operator—causally produces real, retained ARC12 rediscoveries and whether the same shared core can use an observable ARC3 mechanic to make a deliberate action choice.

All artifacts use only source-pinned public inputs. The live controller receives no task ID, ARC1-GT/ARC2-GT feature file, GT solver, historical decomposition, test target, future ARC3 transition, or post-hoc oracle. Test targets and oracle materializations remain V&V-only after a complete commitment.

## Causal Acceptance Trace

An exact answer counts as persistent-theory evidence only if its live trace contains all of the following, in causal order:

1. a retained partial theory with a visible residual or contradiction;
2. a counterexample-directed observation or discriminating additional demonstration;
3. a retained-rule parameter/scope revision or a generic partial residual rule;
4. an ordered composition with the retained rule(s);
5. full training compatibility followed by a complete test commitment; and
6. post-answer all-cell V&V.

The generic family must be inferred from visible examples and must be independently represented in code; a task-ID branch, copied GT schema, or task-shaped full-output dispatch invalidates the result.

## Causal Ablations

P0007 must run the same ten inputs under three locked configurations:

1. **Full IHL:** persistent theory plus generic partial residual proposals.
2. **No revision:** identical starting hypotheses and observations, with counterexample-driven theory evolution disabled.
3. **No new residual family:** persistent theory remains enabled, but the newly introduced component/row-span residual families are disabled.

The report must state exact counts, per-task differences, and whether an exact full-IHL result disappears in each ablation. This is causal evidence, not a claim that every task needs the same rule family.

## Frozen-Generalization Gate

The unchanged disjoint 25+25 denominator may be run only after P0007 has at least three exact outcomes, at least two distinct generic residual families, and an exact-count advantage of at least three over both ablations. If the gate is not met, the frozen split stays untouched and the failure record directs the next generic-perception research cycle.

If the gate is met, the learner implementation and packet configuration are frozen by commit hash before P0008 is generated. No test outcome from the frozen split may change the generic operator set for that run.

## ARC3 Evidence Gate

P0009 must start from an explicitly bounded public history, learn action-to-observable-motion relations from only those past transitions, and then choose a currently available action without reading future records. It must show a non-default action choice whose predicted movement reduces an observable goal relation and whose recorded result contributes to level progress or clearance. A replay remains evidence only; it is not blind live play or an ARC3 solver claim.

## Offline ARC12-IHL-GT Gate

Each annotation records only externally reportable observation, hypothesis, prediction, checked evidence, counterexample, revision, and final verification fields. It remains offline-only and cannot enter a live learner import path.
